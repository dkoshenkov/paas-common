# Backlog Flux для PaaS

- Источник потребностей: `openspec/changes/define-k3s-paas-foundation`.
- Это задачи для отдельного согласования в Flux; исходники Flux здесь не изменяются.
- Итог проверки: обязательных доработок Flux для первого собственного HTTP/OpenAPI
  API PaaS нет при выборе статических путей с query-параметрами и JSON-body.
  Этот вариант подтверждён сквозными тестами. Path-параметры доступны в Flux
  v0.4.0; новый proto/gRPC target остаётся отдельным условным расширением.

## FLUX-001 — Path-параметры собственного и внешнего API

- Статус на 2026-10-24: строковые path-параметры выпущены в Flux v0.4.0;
  [PR #10](https://github.com/dkoshenkov/flux/pull/10) влит в main.
  Проверены client/server/OpenAPI, query/body, URL-кодирование, root-array ответ
  и заголовок Link для GitHub-профиля. Живой GitHub-импорт PaaS не реализован.
- PaaS закрепляет Flux v0.4.0, commit
  `7bf0d07b74871baa601b6388b53560ec6f6cbe01`. Активный API сохраняет static
  paths/query/body; GitHub-клиент остаётся отдельным этапом.
- Базовая сверка 2026-10-24 до реализации PR #10: Flux находился на commit
  `8197264816e0a0f4f5fb681c7346e26ad2e1916c` (v0.3.0). В исходниках
  `validateLiteralPath` запрещает `{}`; параметры поддерживают только `in: query`.
  Сквозной probe от 2026-10-19 описан в
  [flux-generator-check.md](../development/flux-generator-check.md).
- Текущий собственный API PaaS использует статические пути с query/JSON-body.
  `/apps/{name}` относится к прежнему неподключённому черновику. Path-параметры
  нужны для выбранного generated GitHub-клиента `/users/{username}/keys`.
- Необходимость: необязательно для собственного PaaS API на static paths/query/body;
  необходимо для ранее выбранного generated GitHub-клиента
  GET /users/{username}/keys с произвольным username.
- Альтернатива GitHub без изменения Flux: фиксированный GET /user/keys,
  но он требует авторизации и возвращает ключи владельца токена. Это изменение
  сценария, а не эквивалентный импорт по произвольному username; нужно отдельно
  согласовать. До выбора варианта не объявлять исходный GitHub-импорт реализованным.
- Дальнейшая работа: добавить контракт GitHub-клиента в согласованном этапе
  импорта. Streaming и новые транспорты в PR #10 не включены.
- Приёмка: клиент подставляет и кодирует значение, сервер извлекает его,
  OpenAPI согласован с фактическим поведением; результат собирается.

## FLUX-002 — Воспроизводимая генерация PaaS SDK

- Статус: выполнено для текущего HTTP/OpenAPI SDK; сверено 2026-10-24.
- `Makefile` закрепляет Flux commit
  `7bf0d07b74871baa601b6388b53560ec6f6cbe01` (v0.4.0) и проверяет его
  перед генерацией. `make sdk` генерирует common и PaaS HTTP/OpenAPI;
  `sdk-proto`/`sdk-grpc` завершаются с явной диагностикой отложенного профиля.
- Активные Flux spec включают preview/apply, operations get/list и четыре GET
  каталога приложений/компонентов. YAML адаптированы к текущему DSL;
  неподключённые исторические черновики не входят в генерацию.
- `paas-common` использует `packages-go v0.3.1-0.20261024142719-ec269923c64b`.
  Существующие common
  `docs/proto` и `pkg/grpc` сохранены без регенерации.
- Результаты генерации, повторяемости и проверок зафиксированы в этапах
  2.2–2.3.3 OpenSpec и отчётах
  [первого SDK](../development/sdk-vertical-check-2026-10-20.md),
  [каталога](../development/sdk-catalog-check-2026-10-20.md),
  [списка операций](../development/sdk-operation-list-check-2026-10-20.md).
- Проверка 2026-10-24: `go test -mod=readonly -count=1 ./pkg/http/...`
  прошла на Go 1.27.1 с `GOWORK=off` и опубликованной зависимостью v0.3.0.
  После обновления два запуска make sdk чистым Flux v0.4.0 сохранили
  20 HTTP/OpenAPI и 6 gRPC/proto файлов. Все три модуля прошли полный набор
  проверок на Go 1.27.3; результаты записаны в
  [отчёте обновления](../development/sdk-runtime-upgrade-2026-10-24.md).
- При изменении контрактов повторяемость проверяется снова. Подтверждённых
  доработок исходников Flux для текущего HTTP/OpenAPI-профиля нет.

## FLUX-003 — Генерация proto/gRPC

- Статус: отдельное будущее расширение; не обязательно для первого HTTP/OpenAPI
  SDK PaaS. Реализация и приоритет требуют отдельного согласования.
- Основание: Flux v0.3.0 на commit 8197264 принимает только all/go/oapi;
  текущий Makefile PaaS явно сообщает, что proto/gRPC-генерация отложена.
- Цель: генерировать proto/gRPC из согласованного API-контракта, если этот
  транспорт понадобится продукту, а не только из-за старого pipeline.
- Работа: согласовать отображение типов и presence/null, стабильные protobuf
  field numbers, контракты ошибок, совместимость и цепочку protoc-плагинов.
  Старый number не возвращать в HTTP DSL автоматически ради совместимости YAML.
- Приёмка: generated proto/gRPC собираются, client/server проходят сквозной тест,
  повторная генерация идентична; правила совместимости явно определены.
- До согласования не менять существующие common gRPC-артефакты и не расширять
  HTTP-задачу FLUX-001 новыми транспортами.
