# Проверка обновления образа на v12

На выделенной `v5-fresh` [подготовили](../../../paas-ctl/scripts/testdata/image-preview-baseline-live.py) два новых приложения. В компоненте `97823a631e3647532ac90ea21572b4fe` приложения `bec2f2be1a594c7a96f6b910c36563a3` работал Deployment `web` с обычными контейнерами `app` и `sidecar`; соседний Deployment был в отдельном приложении. Оба исходных rollout прошли. Reader обновили штатным установщиком, существующий Job миграции v12 не заменяли.

Через [реальный PTY](../../../paas-ctl/scripts/testdata/image-preview-tui-live.py) оператор выбрал второй контейнер `sidecar`, ввёл новый образ, просмотрел preview и подтвердил его клавишей `y`. Операция `2953f88d7e791cd907478ea92ca768b1` завершилась SUCCEEDED и rollout прошёл. Затем [отдельный preview/apply](../../../paas-ctl/scripts/testdata/image-preview-update-live.py) первого контейнера `app` завершился операцией `554eab3d7ea907ef969b9bf3dc023841`, также SUCCEEDED. В обеих операциях миграция отсутствовала. После каждого обновления UID Deployment `91c0b329-77cf-420c-8648-a89b3bfbb693` сохранился; сравнение полного spec подтвердило изменение только image выбранного контейнера. UID и spec соседнего Deployment сохранились.

Для теста изменяли строку ссылки: исходная ссылка по digest и новая ссылка с тегом `18.6-alpine` указывают на один и тот же импортированный digest. Это подтверждает обновление управляемого поля и rollout, но не смену исполняемого содержимого образа.

[Отдельная проверка устаревшего preview](../../../paas-ctl/scripts/testdata/image-preview-stale-uid-live.py) подготовила preview, затем тестовый администратор заменил только одноразовый Deployment на объект с другим UID. Apply вернул 409; подменённую копию после теста удалили. Истечение preview и потеря ответа CREATE этими живыми сценариями не проверялись.
