## Что уже согласовано

### Платформа и формат деплоя

- k3s — первый backend. PaaS 0.x.x поддерживает одну ноду; мультинод обязателен
  для 1.0.0, но сам по себе не означает HA. Compose/Swarm — будущее.
- Штатное управление через PaaS. Документация рекомендует не изменять ресурсы
  напрямую через Kubernetes API ради согласованности состояния.
- Приложение состоит из независимо обновляемых компонентов. Один пакет компонента:
  ровно один `apps/v1 Deployment` и необязательные `v1 ClusterIP Service`,
  `v1 ConfigMap`, `networking.k8s.io/v1 Ingress`.
- Namespace, Secrets, SA/RBAC, NetworkPolicy, Job мигратора, инфраструктурные PVC
  создаёт платформа. Пользовательские Job/CronJob/StatefulSet/PVC не входят в первый профиль.
- Namespace берётся из выбранного приложения: отсутствующий заполняется,
  чужой отклоняется. Явное стабильное имя, без generateName.
- Владение и стабильные ID хранятся в PaaS; пользовательские labels не дают
  ownership/полномочий. Пропуск прежнего ресурса не удаляет его автоматически.
- Согласованы ID-метки приложения/компонента/Deployment, точные selectors,
  привязка Service к Deployment пакета. Подробные алгоритмы и сценарии в specs.

### Ingress, домены и сертификаты

- Встроенный Traefik k3s, без Caddy и отдельного сервиса продления.
- Один host и один path на пользовательский Ingress; несколько Ingress разрешены.
  Явные Prefix/Exact, строгий Prefix Traefik, приоритет вычисляет PaaS.
- Канонизация доменов и контроль class/TLS/annotations согласованы. Список
  допустимых annotations конечный; произвольные пользовательские Service annotations
  не поддерживаются. Первый backend — HTTP, не внутренние HTTPS/h2c.
- Домены регистрируются за приложением через PaaS. Конфликты маршрутов учитывают
  сохранённые ресурсы и незавершённые операции всего приложения.
- Один активный ACME resolver, HTTP-01, штатный HTTP→HTTPS redirect с защищённым solver.
  Постоянный приватный ACME state, отдельные staging/production state, один writer
  также при upgrade, backup/restore до эксплуатации.
- Внешний TLS probe выполняет paas-ctl по запросу операции/статуса. TLS имеет
  отдельные PENDING/READY/ERROR, checkedAt и срок сертификата. Не выдавать default
  или staging certificate за готовый production HTTPS.
- Было три делегированных круга ревью GPT-6 Astra low; поправки записаны в specs.
  Реальные Traefik/ACME/DNS/TLS на k3s пока не проверялись.

### PostgreSQL, секреты и мигратор

- Общий PostgreSQL нужен сразу для control plane. Логические БД/роли приложения
  создаются при наличии мигратора; новое приложение без мигратора не получает их.
- Отдельные БД, роль приложения и роль мигратора. Приложению SELECT/INSERT/UPDATE/DELETE,
  без TRUNCATE, DDL, владения объектами и высоких административных прав.
- Мигратор меняет структуру и данные в своей выделенной схеме; чужие БД закрыты.
  Удаление мигратора из конфигурации сохраняет существующие БД/роли/credentials/доступ.
- DB credentials — отдельные Kubernetes Secrets, с выдачей конкретным контейнерам.
  Sidecar/init ничего не наследуют автоматически. Env/volumes/projections проверяются;
  optional не отменяет разрешение. Ссылки на Secret сами по себе доступа не дают.
- Отдельный SA приложения и мигратора, без чтения Secrets через API/создания workloads,
  automount=false, явные SA-token projections запрещены.
- Job мигратора и его Secret в Namespace приложения; отдельный migration Namespace
  не нужен. Credentials мигратора среди workloads получает только его Job;
  администратор может получить их отдельным явным действием.
- Выбран **Goose как библиотека небольшой Go-программы** в образе с SQL-файлами.
  Версия закрепляется при сборке; собственный движок миграций не пишем.
- Через PaaS только up. Новых миграций нет — успех. Down/redo/reset не предоставляем.
- Одна активная миграция БД. Второй запуск сразу отклоняется со ссылкой на текущий,
  без очереди. После ошибки нет автоматических повторов, включая настройки Job/Pod;
  следующая попытка — явное действие оператора.
- Первая миграция автоматически предшествует первому запуску компонентов;
  последующие выбираются явно. Ошибка первой не допускает запуск компонентов.
- Пользовательские SMTP/API secrets отложены. Их будущий показ необходимых
  перезапусков средствами Charmbracelet тоже отложен, не добавлять сейчас.

### Registry и границы daemon

- GHCR, включая приватные образы; своего registry нет. Пользовательский imagePullSecrets
  в первом профиле запрещён. Runtime использует узловой `/etc/rancher/k3s/registries.yaml`.
- GHCR-токен должен быть скрыт от daemon, в том числе от косвенного извлечения
  через создаваемые workloads. CLI передаёт его напрямую доверенной операции узла по SSH.
- На старте root:root 0600 без прикладного шифрования; root доверяем. Это не защита
  от чтения диска/root. Усиление хранения и независимая выдача — отдельный backlog.
- Registry-helper root-owned, каталог не writable для paas. Фиксированные действия:
  set-ghcr, restore-registry, apply-registry, status. Ограниченный NOPASSWD на точные
  вызовы, без shell/произвольных путей/команд. Токен через stdin, не argv/логи.
- Set меняет только auth ghcr.io, сохраняет остальные registry-настройки,
  атомарность и одну защищённую предыдущую конфигурацию. Нет автоматического рестарта.
- Restore восстанавливает файл без рестарта; apply отдельным действием перезапускает
  k3s и проверяет готовность. Нет автоматических циклов рестартов/откатов.
- Daemon внутри k3s с отдельным SA управляет только подготовленными app Namespace.
  Нет SSH/sudo/admin kubeconfig, изменений Namespace/RBAC/admission/system workloads,
  собственного deployment, произвольных PV, nodes/proxy и escalation.
- Restricted enforce приложений обеспечивает кластер независимо от daemon.
- `runtime/secret` рассматривался только как экспериментальная дополнительная защита
  временных данных на поддерживаемых Linux-целях, не шифрование хранения; код не добавлен.

### Оператор, SSH, UDS, GitHub и TUI

- Одна роль администратора PaaS. Отдельные ключи рабочих мест, независимый отзыв.
  Мультироли и прямой управляющий HTTPS API отложены.
- Штатный API transport: приватный локальный UDS → OpenSSH → pathname UDS узла
  `/run/paas/daemon/api.sock` → daemon. Нет управляющего TCP listener/Service/Ingress.
- Отдельный системный Namespace daemon. Его узкий hostPath не совместим с
  Baseline/Restricted, но приложения остаются Restricted. Системные workloads
  создаёт/обновляет только доверенная установка, не daemon/приложения.
- Монтируется только каталог сокета, `hostPath.type Directory`, не DirectoryOrCreate,
  не inode сокета, без subPath/mount propagation. Без root/privileged/host namespaces.
- Права: `/run/paas` root:root 0755, каталог daemon — отдельный UID daemon : paas-api
  0750, socket — тот же владелец/группа 0660. Paas входит в группу для подключения,
  без права замены socket; UID daemon отличается от UID SSH-пользователя paas.
- Каталог восстанавливается при boot, например systemd-tmpfiles; один Pod/upgrade
  Recreate или эквивалент, без конкуренции за сокет. Не создавать hidden TCP health endpoint.
- CLI local socket в уникальном коротком каталоге 0700. Проверять host key,
  выбранную identity, без agent forwarding. После открытия tunnel проверять API:
  ExitOnForwardFailure не доказывает готовность daemon. PermitOpen не ограничивает UDS paths.
- Root/paas и локальному пользователю оператора доверяем. Не обещать обязательное
  использование официального CLI, per-key API-аудит или закрытие старых tunnel при отзыве ключа.
- Существующие generated constructors принимают *http.Client; UDS подключается
  custom transport, без ручных правок generated-кода и proxy/сетевых redirects.
- Первичная подготовка через существующий административный доступ с нужными правами.
  Далее sudo paas только на фиксированные операции установки, Namespace/начальных
  прав, установки/обновления daemon, registry. Не NOPASSWD ALL и не arbitrary root kubectl.
- GitHub-импорт выбранных публичных ключей входит в 0.x.x. Generated API client
  Flux включается в сборку paas-ctl заранее, не генерируется в runtime. TUI показывает
  fingerprint, импортирует только выбранное; отзыв явный. Удаление ключа из GitHub
  само серверный доступ не меняет. Фоновая sync отложена.
- **Открыто после проверки Flux:** исходный GitHub `/users/{username}/keys` требует
  path-параметров. Статический `/user/keys` работает только с авторизацией владельца
  токена и не эквивалентен произвольному username. Не менять сценарий молча.
- TUI: Bubble Tea; Bubbles/Lip Gloss по потребности. Четыре экрана: Серверы,
  Приложения, Приложение, Операции. Деплой: выбор app/component → файл/каталог YAML →
  ошибки/WARN/план изменений → подтверждение → операция. Есть сокращённое обновление
  образа компонента. Встроенный YAML-редактор не нужен, секреты скрыты в обычных экранах.
