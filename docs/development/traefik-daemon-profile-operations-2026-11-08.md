# Передача профиля HTTPS в daemon

После штатной установки HTTPS и готовности Traefik администратор на ноде
может проверить профиль командой:

```sh
sudo /usr/local/libexec/paas/traefik-recovery status
```

Команда возвращает `staging` или `production` только после проверки сохранённой
установочной записи, HelmChartConfig, Deployment и успешного init guard, UID
PVC/PV, узла и ACME state. Ошибка даёт ненулевой статус без значения профиля.
Команда не доказывает внешний DNS, цепочку сертификата или готовность HTTPS.

Затем оператор запускает штатную установку/сверку daemon через свой настроенный
SSH-профиль:

```sh
paas-ctl node install-daemon --host SERVER --identity /absolute/path/to/paas-key
```

Установщик повторяет проверку и записывает `PAAS_INGRESS_PROFILE` в Pod template
только для подтверждённого профиля. При изменении он проверяет UID и
resourceVersion, перечитывает Deployment и ожидает rollout. Под daemon не
монтируются ACME state, приватные ключи или PVC Traefik. После rollout
установщик повторяет проверку Traefik; если она перестала проходить, он удаляет
значение и повторно ожидает rollout daemon.

При потере guard, state или подтверждения после установки повторный
`node install-daemon` удаляет значение из template и пересоздаёт Pod. Ingress
preview без профиля закрывается. Если Kubernetes или нода недоступны,
установщик не может подтвердить изменение или пересоздать Pod; ранее
запущенный daemon может сохранить прежнее значение до восстановления доступа и
повторной сверки. Проверка не является непрерывным мониторингом между запусками.

Локальные тесты проверили add/remove для существующего Deployment, проверку
UID/template, потерю подтверждения, совместимость старого клиента и повторный
запуск. Фактическая проверка доставки профиля после установки и удаления при
потере guard на k3s выполняется отдельно.
