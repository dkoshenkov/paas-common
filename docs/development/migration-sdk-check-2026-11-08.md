# Контракт миграций, проверка 8 ноября 2026

Из `docs/api/paas/migrations.yaml` и `migration_types.yaml` Flux v0.7.0 генерирует отдельный сервис `migrations`. Четыре команды включают две пары preview/apply. Три чтения предоставляют карточку, общую историю операций и структурированный журнал Job. Типизированные статусы и матрица форм приведены в [утверждённом контракте](app-migration-contract-proposal.md).

## Исполняемые чтения

В daemon зарегистрированы три GET нового service. Inspection и history читают один read-only repeatable-read snapshot. У старой истории область cursor остаётся operations, у общей — history. Фильтр по APP применяется в SQL до старого limit и lookahead. Проверка на живом PostgreSQL охватила обновление v4 → v5 с прежней записью, чтение обеих целей, несовместимые курсоры, повреждённую запись lookahead, пустой журнал и безопасные ответы через Unix-сокет.

Журнал хранится в самой строке операции. PostgreSQL ограничивает возвращаемый BYTEA до передачи в daemon. У каждого события закреплённый seq, при первом сохранении время задаёт PostgreSQL. Повтор того же seq/code/version сохраняет прежнюю запись, несовпадающий повтор получает конфликт. После исчерпания места для обычных событий видимые клиенту seq сохраняются, truncated устанавливается, последний слот остаётся для terminal Job. Срок хранения совпадает с операцией. Проверены конкурентные повторы, усечение, продолжение по after, терминальное событие, отсутствие пароля в ответе 500 и очистка содержимого при tombstone. Для воспроизведения используйте `sh scripts/test-postgres.sh -race -count=1` из paas-daemon; испытания прошли на PostgreSQL 18.6.
