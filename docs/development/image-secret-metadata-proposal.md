# Остаток контракта SDK для оператора

Этап 2.3.3. Пользователь уже согласовал сокращённое обновление образа и получение имён полей прикладного Secret без раскрытия их значений. 8 ноября пользователь одобрил оба GET: чтение текущих образов контейнеров и чтение имён полей прикладного Secret. 8 ноября владелец также одобрил POST /deployments/image/preview и подтверждение через существующий POST /deployments/apply.

## Версии образов

`GET /components/images?app_id=…&component_id=…` возвращает ID приложения и компонента и массив управляемых Deployment. Запись содержит имя Deployment и список его обычных и init-контейнеров с именем, типом и текущим образом. Daemon сверяет объект с ownership и UID Namespace. Инъецированные контейнеры и чужие объекты не включаются. В ответе нет env, команд, путей томов или полного PodSpec. Для зарегистрированного компонента без применённого Deployment список пуст. Неверный запрос — 400, неизвестное приложение или компонент — 404, недоступное достоверное чтение — 503.

`POST /deployments/image/preview` принимает `app_id`, `component_id`, `deployment_name`, `container_name`, `image`. Экран предлагает выбирать из обычных контейнеров ранее успешно запущенного управляемого экземпляра. Запрос проверяет действующую политику, прежний образ и принадлежность объекта. Подтверждение использует штатный `POST /deployments/apply` с выданным preview_id. В снимке достаточно ссылки на экземпляр, прежнего/нового образа и проверяемых предусловий; исходные YAML восстанавливать из публичной истории не требуется. Применение меняет только image по имени контейнера и обновляет его значение в сохранённом желаемом состоянии. Остальные поля остаются под управлением их текущих владельцев. Истечение preview или изменение плана требует нового подтверждения. Миграция в этом сценарии отсутствует.

Планируется долговечная отметка успешного rollout, привязанная к instance ID. Запись ownership сама по себе появляется раньше успеха. Для старого объекта допустимо подтвердить успех по сохранённой достоверной связи операции и экземпляра; при недостатке сведений требуется обычный деплой. Приёмка включает выбор с другого рабочего места, два контейнера, смену UID между preview/apply, давность старой операции и сохранение соседних ресурсов.

## Справка для привязки прикладной БД

`GET /apps/database/metadata?app_id=…` возвращает 200 с `app_id`, `secret_name` и `keys` для прикладного Secret. Список ключей в текущем профиле — database, host, password, port, username. Это имена для составления манифеста. Значения и реквизиты роли MIGRATOR исключены из ответа. Новое чтение не выдаёт права использовать Secret: разрешение конкретному экземпляру и контейнеру проверяется отдельно при preview и apply.

Неизвестное приложение или отсутствие подготовленной БД — 404, прерванная или незавершённая подготовка — 409, несогласованная identity либо недоступное хранилище — 503, неверный app_id — 400. Источником имени и набора полей служит согласованный профиль выдачи для READY mapping. Для реально раскрываемых значений используется отдельный подтверждаемый POST с выбором назначения. Тесты проверяют точное тело ответа и отсутствие значений credentials, отсутствие Secret мигратора, отдельность от check/выдачи допуска и корректную обработку PENDING.

Снятие конфигурации мигратора сохраняет данные. Явные отзыв SQL-доступа и удаление БД получили отдельный согласованный контракт. Оба действия прошли через TUI на одноразовой БД, данные и подключения соседнего приложения сохранились.
