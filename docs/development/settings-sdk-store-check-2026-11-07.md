## Контракт и воспроизводимость

Семь маршрутов settings описаны в `docs/api/paas/settings.yaml`. Пять команд POST принимают до 1 048 576 байт исходного JSON. Generated handlers ограничивают фактически прочитанное тело до вызова хранилища. Превышение возвращает 413 BODY_TOO_LARGE. Весь JSON хранимой политики ограничен тем же размером. PostgreSQL проверяет octet_length до передачи BYTEA читателю.

## PostgreSQL

Goose v4 дополняет существующий каталог. Для read-only v3 прежние каталог и история доступны, settings возвращают 503. После миграции GET старых строк выдаёт стабильную начальную revision. Доверенный preparer записывает Namespace UID. Daemon может только прочитать подтверждение. Регистрация и изменение настроек используют отдельную роль и общий с preparer двухключевой advisory transaction lock (1885430131, 4100). Проверки источника и записи выполняются в короткой READ COMMITTED транзакции после получения блокировки отдельным SQL statement. Стандартный pgx.BeginTxFunc отвечает за COMMIT и откат. Публичная pgxtx.ReadSnapshot применяется только для чтения.

| Реальная проверка на PostgreSQL 18.6 | Наблюдение |
| --- | --- |
| Повтор миграции v3 → v4, старый каталог | Исходные строки сохранились. Читатель видит стабильную revision до первой записи. При повреждённой истории Goose readiness возвращает 503. |
| Повторы регистрации и конкуренция | Восемь конкурентных регистраций с одним ключом создают одно приложение и возвращают один ID. Две конкурирующие регистрации компонента с разными именами и одним новым ключом дают один успех и один конфликт. После таймаута ожидания замка повтор создаёт запись один раз. Повтор сохраняет прежнее исходное имя, в том числе после tombstone. Новая регистрация компонента у удалённого родителя получает 404. |
| CAS | Две смены политики с одной revision дают один успех и один конфликт. Запись прежнего значения по текущей revision сохраняет revision. Set/remove мигратора изменяют только конфигурацию и revision. |
| Реальные ACL | Административный SQL повторяется без смены паролей. Writer может читать подтверждение и изменять только предусмотренные колонки, preparer — резервировать и подтверждать собственную служебную запись. Попытки записать операцию, сменить подтверждение от daemon или записать данные от read-only роли отклонены. |
| Изоляция хранения | Для чужого компонента отказ 404. Физическая политика длиной 1 MiB читается, на дополнительном байте возвращается безопасный 500. Канонический JSON политики длиной ровно 1 MiB записывается. Превышение на записи оставляет прежнюю revision. Проверена ошибка частично сохранённого снимка. |

## Проверка реализации

В paas-common и paas-daemon прошли go build, vet, tidy -diff, fmt, lint, тесты и race. Бинарник daemon собран также для linux/amd64. Реальный UDS проверен вместе с PostgreSQL 18.6. В регрессионных тестах readiness учитывает раздельные grants reader и writer. Отозванный SELECT reader на новые поля v4 даёт 503.

Mutator проверил 71 мутацию двух SDK-валидаторов и 119 мутаций трёх файлов store на настоящей PostgreSQL. Все выявлены тестами. Для Go embed каждая изолированная копия mutation worker получила физический каталог миграций. Добавленные тесты различают NULL и повреждённую revision, отсутствие разрешения на запись и успешный SQL UPDATE с нулём изменённых строк. Максимальный CRAP в измеренной части store равен 13,5, для SDK — 12. Dryer с порогом 0,8 не обнаружил дублирования в store. Три пары в SDK относятся к прежним validation/catalog.go и request.go.

Из корня соответствующего модуля можно повторить `make sdk GENERATOR=/path/to/verified/flux`, `go test -race ./...` для общего SDK, `sh scripts/test-postgres.sh -race -count=1` для daemon и `sh scripts/testdata/postgres-control-sql.sh` для ctl. Публикация SDK, включение профиля на k3s и применение политики к реальным workloads учитываются отдельными проверками.
