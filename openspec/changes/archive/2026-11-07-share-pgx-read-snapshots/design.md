# Design

## Context

`packages-go/sqltx` в v0.5.0 выполняет commit успешного callback для `*sql.DB`.
Пять чтений каталога и истории в daemon используют `*pgxpool.Pool`.

## Goals / Non-Goals

В библиотеке находится жизненный цикл read-only транзакции. Дедлайн запроса,
проверка PaaS-схемы, обработка повреждённых строк и пагинация принадлежат daemon.

## Decisions

Пользователь одобрил этот этап 2026-11-07. `pgxtx.ReadSnapshot[T]` принимает
контекст, пул pgx, положительный таймаут отката и callback `func(pgx.Tx) (T, error)`.
Транзакция имеет режим `REPEATABLE READ READ ONLY`. Callback читает данные и
закрывает свои rows до возврата. Владение транзакцией остаётся у библиотеки.
Отложенный rollback получает отдельный ограниченный контекст, сохраняющий
значения контекста вызова. Ошибка callback сохраняется. Ошибка освобождения
после успешного callback инвалидирует результат. Panic доходит до вызывающей
стороны после попытки освобождения.

В daemon проверка схемы и запрос находятся в том же снимке, дедлайн чтения
остаётся две секунды. Доменные ошибки сохраняются, технический сбой приводит к
`ErrUnavailable`. Неизвестный результат COMMIT относится к будущей записи.
Мигратор Goose продолжает удерживать session lock на отдельном соединении.

## Risks / Trade-offs

До публикации пакета интеграцию проверяли в изолированном workspace.
После слияния daemon закрепил опубликованную версию v0.6.0.

## Проверка 2026-11-07

Реализация подготовлена на ветке `feat/pgxtx-read-snapshot` от проверенного
`origin/main` (`fcadb4c79e3d108de47361605162a52fd7586414`, также тег v0.5.0).
Пользователь одобрил fetch, создание отдельного worktree и перенос патча 2026-11-07.
В этой ветке прошли build, полный race-набор на PostgreSQL 18.6, vet, tidy и lint.
По отдельному одобрению создан локальный commit `e2936059ce362a9dcb62169026d7d049390d23c8`.
Его родитель совпадает с указанным origin/main. В коммит вошли шесть файлов. На момент этой проверки ветка оставалась локальной.
Исходная рабочая копия на dev (`99d28951fbe36a24f0d0d2409300d19884532aa6`)
сохранила прежнее состояние. Раннюю локальную интеграцию фиксируют два проверенных патча.

- [Библиотека](packages-go.patch) применяется к исходникам v0.5.0. Добавляет
  пакет pgxtx, его документацию и тесты, фиксирует pgx v5.11.0. Пакет sqltx
  остаётся без изменений.
- [Потребитель](paas-daemon.patch) применяется к рабочему дереву daemon **после
  этапа 3.3.6–3.3.10**. Пять операций чтения используют общий механизм.
  После публикации патч применён в рабочем модуле daemon, `go.mod` и `go.sum`
  закрепляют реальную версию библиотеки.

| Проверка | Результат |
| --- | --- |
| Реальный PostgreSQL 18.6 | В пределах callback видна одна версия строки до и после конкурентного UPDATE. Попытка записи получает SQLSTATE 25006. |
| Ошибки callback/begin/rollback | Возвращается нулевое значение. Ошибка callback сохраняется при одновременном сбое rollback. После отмены и panic соединение с тем же PID переиспользуется в пуле с MaxConns=1. При потере соединения пул выдаёт работоспособную замену. |
| Дедлайн очистки | Трассировка реального ROLLBACK подтверждает новый ограниченный контекст после отмены запроса. |
| Библиотека | Проверены базы dev и v0.5.0, сборка, тесты всех пакетов, `vet`, `tidy -diff`, race и lint пакета pgxtx. Для ReadSnapshot Crapper показал CRAP 6 и покрытие 100%. Mutator убил 7/7 мутаций. Dryer не нашёл пар с порогом 0,8 между pgxtx и sqltx. |
| Потребитель | Временный Go workspace на базе v0.5.0 прошёл build, test, race, vet, fmt и lint. Реальные DB/UDS/restart тесты каталога и истории выполнены. Дополнительный тест принудительно закрывает сессию перед rollback и проверяет ErrUnavailable, пустой результат и дальнейшую готовность. |
| Повторное применение патча | В новой копии daemon с `GOWORK=off` и временным локальным replace прошли все тесты с `-race` на PostgreSQL, включая UDS, и сборка `linux/amd64`. Штатный исходный модуль также прошёл независимые build и DB/UDS/race с прежним pin. |

### Публикация и независимая сборка

[PR #16](https://github.com/dkoshenkov/packages-go/pull/16) слит в main
7 ноября 2026 года. PR-проверка [tests](https://github.com/dkoshenkov/packages-go/actions/runs/42383503724)
завершилась успешно. `go get` по merge SHA
`53373963a534b26562e61204bc02b28573e5bfe0` разрешился в опубликованный тег
`v0.6.0` с checksum `h1:xfupVPppWGF7iauyR07yjiUCkbXyPIwFPSrzEnL7nhI=`.

На этой версии рабочий модуль `paas-daemon` прошёл с `GOWORK=off` build,
`go vet`, tidy-diff, форматирование, lint, обычные тесты и race-тесты. Оба
прогона DB-набора выполнили сценарии PostgreSQL 18.6, UDS, перезапуска,
согласованного каталога, истории и отказа rollback. В runner проверка
готовности контейнера обращается к TCP-порту основного PostgreSQL, чтобы
перезапуск временного initdb-процесса не прервал приёмку.

Собраны бинарники Linux amd64 и arm64. Детерминированный OCI-артефакт arm64
со штатным `Dockerfile` на момент проверки — `localhost/paas/paas-daemon@sha256:3c055c44b7100b11ff826d989890f4fbbebe94472c46ba958a02fe5c4fdbad7a`.
SHA-256 бинарника внутри этого образа —
`9701cbcc4037ded23156bc375553ee361e8b37ae906f21635c882cb53c3de232`.

Для повторения
приёмки нужны Go 1.27.3, Docker и соседний checkout `paas-common` для
существующего локального SDK. Команды выполнять из корня `paas-daemon`.

```sh
export GOWORK=off
go list -m github.com/dkoshenkov/packages-go
go build -mod=readonly ./...
go vet -mod=readonly ./...
go mod tidy -diff
sh scripts/test-postgres.sh -count=1 -v
sh scripts/test-postgres.sh -count=1 -race -v
```
