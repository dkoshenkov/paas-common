# Spec Delta

## Purpose

Хранить credentials приложений вне Git, автоматически создавать пароли
и предоставлять оператору явный способ получить сохранённые значения.

## ADDED Requirements

### Requirement: Credentials генерируются и сохраняются вне Git

PaaS SHALL генерировать случайные пароли криптографическим генератором и сохранять
credentials приложения и мигратора в отдельных Kubernetes Secrets.
Отслеживаемая конфигурация SHALL содержать ссылки вместо значений секретов.

#### Scenario: Создание credentials
- **WHEN** PaaS подготавливает пользователей БД приложения
- **THEN** пароли сохраняются в Secrets и не записываются в файлы репозитория
- **AND** бизнесовый контейнер получает только credentials пользователя приложения

### Requirement: Полномочия мигратора доступны только его защищённому запуску

PaaS SHALL обеспечивать защищённое выполнение мигратора. Обычные workloads SHALL NOT
получать credentials мигратора или использовать его ServiceAccount и полномочия.
Раздельное хранение Secrets без ограничения их использования SHALL NOT считаться
достаточной защитой.

#### Scenario: Попытка использовать полномочия мигратора из обычного workload
- **WHEN** пользовательский workload ссылается на Secret или ServiceAccount мигратора
- **THEN** PaaS отклоняет операцию до запуска workload
- **AND** значения секрета не раскрываются в диагностике

### Requirement: Оператор получает сохранённый секрет явным запросом

PaaS SHALL предоставлять авторизованному оператору получение credentials через CLI.
Обычный просмотр статуса и логи SHALL NOT раскрывать значения секретов.

#### Scenario: Получение пароля
- **WHEN** оператор с нужными правами явно запрашивает пароль приложения
- **THEN** он получает сохранённый пароль без его изменения

#### Scenario: Отсутствие прав
- **WHEN** credentials запрашивает субъект без нужных прав
- **THEN** доступ отклоняется без раскрытия значений

### Requirement: Повторный запуск сохраняет credentials

Перезапуск daemon и повторный деплой SHALL NOT менять существующие пароли.

#### Scenario: Перезапуск control plane
- **WHEN** daemon перезапускается после успешной подготовки приложения
- **THEN** приложение продолжает использовать прежние credentials
- **AND** оператор может получить те же значения через CLI
