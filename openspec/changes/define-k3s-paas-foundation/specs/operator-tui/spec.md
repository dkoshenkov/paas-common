# Spec Delta

## Purpose

Предоставить оператору интерактивный терминальный интерфейс PaaS для установки,
независимых деплоев, миграций и просмотра состояния без необходимости помнить команды.

## ADDED Requirements

### Requirement: Основной интерфейс оператора является TUI

paas-ctl SHALL предоставлять интерактивный TUI с клавиатурной навигацией,
выбором целевого сервера и доступных операций.

#### Scenario: Запуск терминального интерфейса
- **WHEN** оператор запускает paas-ctl в интерактивном терминале
- **THEN** открывается интерфейс с выбором сервера и доступных действий
- **AND** для навигации не требуется вводить полные команды вручную

### Requirement: Операции установки и управления доступны из TUI

TUI SHALL предоставлять запуск подготовки SSH-доступа и установки PaaS,
просмотр приложений и компонентов, независимый деплой, отдельный запуск мигратора,
просмотр статуса и доступных логов операций.

#### Scenario: Первоначальная установка
- **WHEN** оператор выбирает установку PaaS на сервер
- **THEN** интерфейс собирает необходимые параметры и показывает ход установки
- **AND** результат каждого этапа или причина ошибки доступны оператору

#### Scenario: Независимое обновление компонента
- **WHEN** после первого успешного деплоя оператор выбирает компонент и версию его образа без запуска миграции
- **THEN** запускается обновление выбранного компонента
- **AND** frontend не обновляется и миграции автоматически не запускаются

#### Scenario: Первая миграция в ходе деплоя
- **WHEN** оператор впервые разворачивает приложение с настроенным мигратором
- **THEN** TUI показывает автоматическую подготовку схемы перед запуском компонентов
- **AND** при ошибке мигратора показывает причину и не объявляет приложение запущенным

#### Scenario: Отдельный запуск миграций
- **WHEN** оператор выбирает запуск мигратора приложения
- **THEN** создаётся отдельная операция с выбранным образом мигратора
- **AND** её статус и логи доступны в TUI

### Requirement: TLS показывается отдельно от готовности приложения

CLI/TUI SHALL предоставлять внешнюю проверку TLS из paas-ctl по запросу операции
или статуса. Результат SHALL содержать PENDING/READY/ERROR, точку/время проверки
и срок наблюдённого сертификата отдельно от Deployment/backend/миграций.
Последний результат SHALL показываться с его временем; default certificate и
staging-сертификат SHALL NOT выдаваться за готовый доверенный production HTTPS.

#### Scenario: Просмотр HTTPS
- **WHEN** оператор запрашивает проверку HTTPS приложения
- **THEN** интерфейс показывает наблюдаемый TLS-результат с checkedAt и сроком сертификата
- **AND** не подменяет им готовность приложения или результат миграции

### Requirement: Секреты раскрываются только явным действием

TUI SHALL скрывать значения секретов в списках и обычных экранах состояния
и предоставлять авторизованному оператору отдельное действие получения credentials.

#### Scenario: Получение credentials из интерфейса
- **WHEN** оператор с нужными правами явно запрашивает credentials приложения
- **THEN** TUI показывает сохранённые значения без их смены
- **AND** значения не дублируются в обычном журнале операций
