# Spec Delta

## Purpose

Обеспечить предсказуемый автоматический расчёт версий и выпуск однодовой ветки в трёх репозиториях PaaS.

## ADDED Requirements

### Requirement: Расчёт версии однодовой ветки
Автоматизация SHALL рассчитывать версию по всем пользовательским изменениям после подтверждённой границы релиза: обычный `fix:` или `fix(scope):` требует patch, breaking с `!` или footer `BREAKING CHANGE:` и любое другое изменение требуют minor. При нескольких изменениях SHALL выбираться максимальный bump. Подтверждённый служебный release-коммит SHALL исключаться; при отсутствии пользовательских изменений новый release PR SHALL NOT создаваться. Для веток `0.x` эти правила действуют только в `0.x`; для текущей однодовой ветки `1.x` minor продолжает `1.x`.

#### Scenario: Векторы bump
- **WHEN** предыдущая версия `1.1.0`, а изменения содержат соответственно `fix: x`, `fix(api): x`, `feat: x`, `chore: x`, `fix!: x`, `fix: x` с footer `BREAKING CHANGE: x`, либо `fix: x` и `chore: x`
- **THEN** следующие версии соответственно `1.1.1`, `1.1.1`, `1.2.0`, `1.2.0`, `1.2.0`, `1.2.0`, `1.2.0`

#### Scenario: Ветка 0.x
- **WHEN** предыдущая версия `0.3.2` и имеется `fix!: x`
- **THEN** предлагается `0.4.0`

#### Scenario: Только служебный релиз
- **WHEN** после предыдущей границы имеется только подтверждённый служебный release-коммит
- **THEN** новый релиз не предлагается

### Requirement: Переход на v2
Автоматизация SHALL NOT предлагать или публиковать `2.0.0` или выше до отдельного решения о переходе; мультинод запланирован на v2. Ручные действия людей находятся вне этого автоматического ограничения. Политика v2 требует отдельного согласования.

#### Scenario: Попытка автоматического перехода
- **WHEN** входные данные или override требуют автоматического выпуска `2.0.0`
- **THEN** автоматический выпуск останавливается

### Requirement: Начальное состояние и проверка релиза
Автоматизация SHALL использовать подтверждённую предыдущую версию и границу истории, проверять рассчитанную версию release PR и останавливаться при неоднозначности или конфликте. Для каждого нетегированного репозитория первая версия и диапазон истории SHALL быть отдельно согласованы перед включением выпуска. Секрет SHALL использоваться доверенным release workflow и SHALL NOT предоставляться недоверенному коду PR.

#### Scenario: Неизвестная первая версия
- **WHEN** для ctl или daemon первая версия ещё не согласована
- **THEN** автоматический выпуск данного репозитория не включается

#### Scenario: Первый релиз ctl и daemon
- **WHEN** для выбранного репозитория подтверждено отсутствие релизного тега и получена полная история до точного SHA main
- **THEN** расчёт SHALL выбрать `1.0.0` для первого релиза и учесть всю достижимую историю, включая корневые коммиты

#### Scenario: Устаревший расчёт
- **WHEN** целевая ветка изменилась после расчёта версии PR
- **THEN** автоматизация не публикует релиз до проверки актуального состояния

### Requirement: Повторяемость
Повторный запуск на неизменном состоянии SHALL сохранять версию и не создавать дублирующий release PR, тег или релиз; конфликт или неполный выпуск SHALL останавливаться для восстановления без повторного повышения версии.

#### Scenario: Повтор после сбоя
- **WHEN** workflow повторяется после частичного выполнения
- **THEN** существующее состояние распознаётся и новый номер версии не создаётся

### Requirement: Локальный проект release PR
Локальный генератор SHALL формировать manifest и CHANGELOG для точного SHA main по тем же коммитам, которые использованы при расчёте версии. При наличии релиза результат SHALL быть доступен для просмотра без записи в Git или отправки в GitHub.

#### Scenario: В диапазоне нет conventional commits
- **WHEN** в проверенном диапазоне есть пользовательское изменение с сообщением без префикса
- **THEN** генератор формирует результат с рассчитанной версией и включает изменение в CHANGELOG

#### Scenario: Повтор и конфликт
- **WHEN** оператор повторяет генерацию с тем же подтверждённым состоянием
- **THEN** содержимое файлов совпадает побайтно; при несовпадении с ранее созданным результатом генератор сообщает конфликт и сохраняет его для разбора

#### Scenario: Текущая версия уже выпущена
- **WHEN** расчёт вернул no_release
- **THEN** проект release PR не создаётся
